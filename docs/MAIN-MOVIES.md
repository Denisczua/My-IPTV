# Единый основной плейлист и резервные киноканалы

Основной адрес остаётся прежним:

`https://raw.githubusercontent.com/Denisczua/My-IPTV/main/playlist.m3u`

Повторно добавлять плейлист в OTTPlayer не требуется. Новые отдельные основные
плейлисты не создаются. Старые `playlist-movies-hd.m3u` и `playlist-movies-ru-cz.m3u`
сохранены как исторические подборки; текущая автоматизация обновляет `playlist.m3u`.

## Архитектура

- `scripts/update_playlist.py` — прежняя точка входа, теперь вызывает единый координатор.
- `scripts/movie_sources.py` — полностью загружает пять каталогов и метаданные IPTV-org.
- `scripts/main_catalogue.py` — сохраняет все варианты, объединяет идентичности,
  выбирает потоки, проверяет структуру и обновляет основной M3U.
- `scripts/check_main_movies.py` — проверяет видео и аудио с прямого чешского подключения.
- `data/main-catalogue.json` — исходные блоки, резервные URL, HTTP-параметры,
  измерения, история, выбранные потоки и исходный состав до миграции.
- `data/movie-providers.json` — все пять постоянных источников и адреса полных баз.
- `data/movie-source-audit.json` — результат каждого URL, размер, дата источника,
  SHA-256, количество записей и явно пропущенные неподдержанные записи.
- `data/movie-reviews.json` — проверка специализации, прав доступа к точным URL,
  ручные языковые подтверждения, алиасы идентичности и OLED.
- `data/main-update-report.json`, `data/main-probe-report.json`,
  `data/main-check-history/` — машиночитаемые отчёты и история принятых партий.
- `playlist-movies-report.md` — итоговый отчёт о наполнении и характеристиках.

Полные `index.m3u` Nexus и DuckKota найдены в README проектов; `all.m3u` у них
возвращал 404. Nexonic публикует `all.m3u`. Для IPTV-org используется полный
`index.m3u`, а для Free-TV — полный `playlist.m3u8`; дополнительно проверяются все
заданные языковые, страновые и проверенные подборки. Радиостанции и VOD-базы
Nexonic не относятся к базам линейных телеканалов и отдельно не подключаются.
Страна и доменная зона не доказывают русский язык.

Free-TV содержит явные `[NO PUBLIC STREAM]`, а IPTV-org — отдельные SRT-адреса.
Они учитываются в аудите, но не становятся фиктивными проигрываемыми URL OTTPlayer.
Другие ошибки структуры останавливают принятие каталога. Снимки всех источников
читаются целиком; нет ограничения на первые N каналов или строки.

## Сохранность и устранение повторов

До первого изменения создана неизменяемая копия `backups/playlist-before-movies.m3u`.
`data/playlist-last-good.m3u` содержит предыдущую версию при очередном изменении.
История версий и обе копии входят в Git. Восстановление выполняется выбором
нужной Git-версии либо копированием резервного файла поверх `playlist.m3u`.

Каналы объединяются по каноническому `tvg-id`/EPG, однозначным именам и альтернативным
именам IPTV-org, нормализованным названиям и явным ручным алиасам. Суффиксы качества
не создают новую идентичность. Разные идентификаторы самостоятельных сеток
сохраняются. Одно совпадение логотипов не является основанием объединить каналы;
неоднозначные названия без ID разделяются по логотипу или URL, а не сливаются вслепую.

В выходе строго одна запись на установленную идентичность канала, без повторения
по категориям. Все альтернативы находятся в базе. Разные HTTP-заголовки и прочие
параметры потока проверяются как разные варианты; совпадение URL не уничтожает их.
Имя, логотип, `tvg-id`, директивы и URL выбранного варианта сохраняются.
EPG-адреса из источников объединяются с прежним заголовком; работоспособность
каждого внешнего EPG-сервера отдельно не гарантируется.

Первоначальная дедупликация не выдаёт неизвестные потоки за проверенные:
до появления достаточных измерений сохраняется прежний первый вариант канала.
Пропавшие из каталога адреса не удаляются из базы. Само исчезновение из источника
не считается доказательством отказа. Существующие каналы сохраняются, кроме
повторных записей и каналов с подтверждённой недоступностью всех резервов.

Защита публикации требует доступности основного источника и хотя бы трёх из
пяти проектов. Запрещены пустой выход, дубликаты, повреждённый M3U, исчезновение
неподтверждённых идентичностей и удаление более 2% уникальных каналов за запуск.
Удаление повторных записей не считается массовым исчезновением уникальных каналов.
Запись файлов атомарная, обычные ошибки записи откатываются. Авария питания
между несколькими заменами файлов требует восстановления последней Git-версии.

## Допуск новых киноканалов

Кандидат определяется по фильмовой специализации и языковым метаданным всех
стран, а не только RU/UA. Другие тематики и специализированные XXX-каналы
не допускаются как новые киноканалы. Рейтинг отдельного фильма не заменяет
классификацию специализации. Существующий общий состав не превращается в
русскоязычный фильтр: старые новости, спорт и другие категории сохраняются.

Новый фильмовой канал или плановое улучшение допускается только при наличии:

1. Подтверждённой фильмовой специализации и доказательства бесплатного доступа
   к конкретному URL. Нахождение в агрегаторе само по себе этого не доказывает.
2. Трёх последовательных успешных прямых CZ-проверок, разнесённых минимум на
   10 минут, за последние семь дней. Автоматическое расписание обычно даёт
   шестичасовые интервалы. Короткие повторные диагностические запросы не считаются
   независимыми подтверждениями. Это оценка по выборке, не гарантия работы всегда.
3. Русской аудиодорожки по тегу FFprobe или отдельной датированной проверке
   прослушиванием конкретного URL. Каталожный язык не подменяет язык дорожки;
   теги `und` остаются на дополнительной проверке. Автоматическое распознавание
   речи не используется. Если русский есть только в недефолтной дорожке master,
   нужен подходящий прямой вариант: наличие русской дорожки ещё не подтверждает
   её автоматический выбор OTTPlayer.
4. Фактического декодирования видео и аудио. HLS проверяется до вложенных
   manifest, трёх сегментов, init map и открытых AES-128 ключей. DRM и авторизация
   не обходятся. FFprobe измеряет размеры, кодеки, язык, FPS и доступный битрейт.
   FFmpeg проверяет примерно 25 секунд видео и звука, временные метки, длительные
   остановки изображения и тишину. Сохраняются скорость загрузки, длительности,
   размеры разрывов и время первого прогресса декодирования.

Явные временные разрывы при поступающих медиа относятся к `UNSTABLE_CZ`, а не
автоматически к OFFLINE. Ошибки доставки три раза подряд дают OFFLINE;
два явных подтверждения регионального запрета дают GEO_BLOCKED_CZ. Обычный 403
без регионального объяснения не является доказательством геоблокировки.
Один сбой не снимает ранее подтверждённый стабильный статус. После отказов для
восстановления снова нужны три успеха; давние успехи не подменяют новые замеры.
Там, где надёжной проверки нет, сохраняется UNKNOWN_CZ, а не фиктивный успех.

HTTP-прокси отключены. Два сервиса (`ipwho.is`, `ipinfo.io`) до и после партии
должны подтвердить один чешский публичный IPv4. В журнал сохраняется хеш IP.
Проверяющий компьютер должен физически использовать прямое подключение в Чехии,
без системного VPN. Скрипт не доказывает отсутствие системного VPN автоматически.
Локальные/приватные адреса не проверяются как публичные телеканалы.

## Выбор, категории и OLED

Среди прошедших вариантов сначала сравнивается доля успешных проверок, затем
фактическое разрешение, кодеки, доступный битрейт и скорость запуска.
При сопоставимой стабильности выбирается более высокое разрешение.
SD не исключается из-за качества: 768×432, 720×576 и другие SD-форматы допустимы.
1080i не исключается; разделение по группам использует измеренные размеры кадра.

Подтверждённые киноканалы получают одну из групп:

- `КИНО — 4K UHD`: не ниже 3840×2160;
- `КИНО — Full HD`: не ниже 1920×1080;
- `КИНО — HD`: не ниже 1280×720;
- `КИНО — SD`: остальные измеренные размеры.

Сортировка в каждой группе алфавитная. Качество из названия не используется
вместо измерений. Старые категории сохраняются для прежних каналов до
подтверждённой переклассификации. Если канал уже в OLED, он остаётся там.
Подтверждённый новый OLED-канал получает группу OLED вместо дублирования в группе
разрешения. Это сохраняет одну запись и совместимость с одногрупповыми плеерами.
В первоначальном основном M3U записей группы OLED не было — они не выдумываются.

OLED подтверждается вручную по экранной графике, независимо от `tvg-logo`:

```json
{
  "channels": {
    "Example.ru": {
      "oled": {
        "approved": true,
        "reviewed_at": "2026-11-26T12:00:00+01:00",
        "evidence": "Просмотрены несколько передач: постоянной экранной графики нет"
      }
    }
  }
}
```

Это фрагмент структуры `movie-reviews.json`; не заменяйте им остальные записи.
Уточнение русской дорожки без тега оформляется в `audio_reviews`:
`url`, `language: "ru"`, `method: "listening"`, `observed_at` и `evidence`.
Проверка относится к точному URL и действует семь дней. Описание сетки передач
не является прослушиванием. Разрешённые адреса указываются в `rights` как
массив `urls` и `evidence` с источником подтверждения.

Samsung/Tizen оценён по измеренным кодекам, но физическое воспроизведение на
конкретном телевизоре не тестировалось. Поддержка HEVC, звука, EPG и некоторых
директив зависит от модели и версии OTTPlayer. Это не объявляется подтверждённым.

## Единая автоматизация

`Update IPTV Playlist` сохраняет расписание `17 */6 * * *` UTC. После обновления
основного каталога в том же процессе обновляются прежние RU/UA-представления.
Их самостоятельное автоматическое расписание убрано; ручной запуск остаётся.
Старый процесс обновления отдельного movie-плейлиста не вводится в main.
Все публикации используют одну группу concurrency, без force push.

GitHub-hosted job только собирает источники, тестирует и применяет уже принятые
результаты. Прямые проверки выполняет Windows runner `iptv-cz`, включаемый
переменной репозитория `CZ_CHECKS_ENABLED=true`. Результаты совпадающих потоков
передаются прежней RU/UA-базе, где сохраняется её собственный временной порог
подтверждения; сведения о HDR не придумываются.

За запуск проверяется максимум 40 вариантов, два потока одновременно с разных
исходных хостов, с паузами и бюджетом 25 минут. Перспективные разрешённые
киноканалы приоритетны, незавершённые серии повторяются, резервы хранятся.
Это поэтапная проверка, а не заявление о проверке всех 10 тысяч каналов за запуск.
Отключение ПК/сон/отсутствие сети задерживает проверку; расписание GitHub тоже
может задерживаться. Предыдущая версия при этом сохраняется.

Принятые результаты сохраняются до публикации. При сбое последующего обновления
исходников сохраняются диагностика и прежний плейлист. После успешного запуска
отчёты и база входят в Git; аварийная диагностика доступна в Actions artifacts.

## Windows: запуск и обслуживание

Для разовой проверки в папке репозитория:

```powershell
python scripts/update_playlist.py
python scripts/audit_personal_cz.py --max-streams 60 --budget-seconds 1500
python scripts/build_playlist_site.py
```

Нужны Python 3.12+, FFmpeg с FFprobe, Git и curl в PATH. Можно использовать
`scripts/run-main-cz.ps1 -FfmpegBin 'C:\path\to\ffmpeg\bin'`.
Этот вспомогательный скрипт не отправляет изменения в Git самостоятельно.

Для автоматического runner подготовлен `scripts/install-main-cz-runner.ps1`.
Он загружает официальную программу `actions/runner`, регистрирует её в этом
репозитории через авторизованный GitHub CLI и создаёт задачу текущего пользователя
`My-IPTV Czech runner` при входе Windows. Папка по умолчанию:
`%LOCALAPPDATA%\MyIPTV-CZ-runner`, вне OneDrive/Git. Токен регистрации не сохраняется
в репозиторий. Runner обновляет себя штатным способом GitHub.

ПК должен оставаться включённым, пользователь — вошедшим в Windows, а VPN/прокси
— выключенными. Это бесплатный локальный исполнитель, не облачный сервер.
Остановить его: `Stop-ScheduledTask -TaskName 'My-IPTV Czech runner'`.
Отключить CZ-job в GitHub: установить `CZ_CHECKS_ENABLED=false`.
Источник и каталог при этом обновляются GitHub-hosted job; проверенный статус
не продлевается фиктивно. Для удаления автозапуска:
`Unregister-ScheduledTask -TaskName 'My-IPTV Czech runner' -Confirm:$false`.

Ручной workflow поддерживает `max_streams`, `budget_seconds` и `movies_only`.
Проверка из GitHub другой страны никогда не маркируется как CZ. База и отчёты
явно различают язык по каталогу, фактический тег дорожки, рабочие измерения и
пока не проверенные существующие каналы.


Актуальная персональная подборка, критерии допуска и новая раздельная автоматизация: [PERSONAL-PLAYLIST.md](PERSONAL-PLAYLIST.md). Старые общие отчёты не доказывают качество персонального плейлиста.

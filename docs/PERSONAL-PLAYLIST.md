# Персональный My-IPTV для OTTPlayer

Постоянный URL не меняется:
https://denisczua.github.io/My-IPTV/playlist-ottplayer.m3u

Это отдельное представление внутреннего каталога. Полный playlist.m3u,
резервные ссылки, история и резервная копия исходного файла сохраняются.
Успешный импорт этого URL в OTTPlayer подтверждён пользователем 26.11.2026.
Успешный импорт не доказывает воспроизведение на конкретной модели Tizen.

## Допуск и состав

Настройки: data/personal-policy.json. Кино не имеет количественного лимита.
Разрешены только художественные киноканалы, Рыбалка и охота (до 4),
Путешествия и природа (до 5), Новости Украины (до 4), Новости России (до 4).
При недостатке подтверждённых каналов группа остаётся неполной: квоты не
заполняются непроверенными источниками. Сериальные/общие/музыкальные и прочие
категории не добавляются отдельно. Кино определяется данными каталога либо
документированным ручным решением, а не одним совпадением слова в названии.

Каждому допущенному потоку необходимы:
- не менее трёх разнесённых минимум на 600 секунд положительных CZ-замеров;
- действительные CZ-наблюдения с хешем исходящего IP, не старше 7 суток;
- реальное декодирование видео и аудио FFmpeg, непрерывные PTS, достаточная
  длительность выборки, отсутствие длинного зависания/тишины в образце;
- русский язык дорожки (у украинских новостей допускаются украинский и русский), проверяемый по
  тегу реально прочитанной дорожки либо локальному анализу декодированного звука;
- нужная дорожка по умолчанию, поскольку телевизор может не переключить её сам;
- документированное происхождение официального бесплатного потока.

Публичный URL в IPTV-каталоге сам по себе не является доказательством лицензии.
Правовые основания фиксируются для точного URL, а не для любого домена/канала.
data/personal-discoveries.json хранит ссылки из официальных публичных проигрывателей.
Ранее проверенные права кино-источников остаются в data/movie-reviews.json.

ASR: бесплатный faster-whisper/base, CPU/int8, офлайн после установки модели.
Сохраняются язык, вероятность, длительность распознанной речи и метод; аудио
и расшифровка в Git не публикуются. Порог: вероятность >=0.95, речь >=5 секунд,
текст >=30 символов. Неуверенный результат не допускается. Это анализ образца,
а не гарантия языка каждой будущей передачи; тег языка тоже не заменяет
декодирование звука. Без ASR потоки с und остаются неподтверждёнными.

Один канал — одна запись. Кандидаты ранжируются по надёжности, измеренному
разрешению, кодекам, битрейту и старту. Разрешение не угадывается по имени;
SD-каналы не исключаются. Официальные кириллические имена: personal-names.json,
дополнения: personal-policy.json/names. Официальные латинские бренды не заменяются
выдуманными переводами. Сортировка — по группе, затем алфавиту.

OLED требует ручного approved=true, method=visual, evidence и reviewed_at в
 data/oled-channels.json. Канал должен также пройти обычный допуск и принадлежать
разрешённой теме. Он переносится в OLED, не дублируется. Отсутствие tvg-logo,
один чистый кадр или название OLED доказательством не являются.

## Проверка из Чехии и продолжение

scripts/audit_personal_cz.py проверяет только кандидатов указанных тем и резервы.
Одинаковый URL с одинаковыми HTTP-заголовками проверяется один раз на канал;
наблюдение переносится на эквивалентные варианты без превращения в несколько
независимых успехов. В отдельный момент — не более одного запроса на хост;
по умолчанию 4 параллельных потока вручную, 2 в Actions.

Каждый поток работает в отдельном процессе: жёсткий предел 150 секунд,
FFprobe 25 секунд, FFmpeg-декодирование 55 секунд. Windows Job Object завершает
также дочерние FFmpeg/FFprobe при закрытии проверяющего процесса. Ошибки
инфраструктуры получают UNKNOWN, а не выдают канал за OFFLINE.

Каждый результат немедленно append+flush+fsync в приватный журнал:
%LOCALAPPDATA%\MyIPTV-CZ-runner\progress\observations.jsonl
База сохраняется после каждой партии. Журнал повторно импортируется без
дубликатов; необработанные потоки продолжаются при следующем запуске.
Обрыв последней JSONL-строки восстанавливается с сохранением повреждённого хвоста.
Блокировка в progress защищает от параллельных запусков из разных checkout.
Сон по бездействию блокируется только во время активной проверки и освобождается
в finally; ручной сон, выключение и закрытие крышки этим не обходятся.
Файл stop-request в progress позволяет остановиться после текущей партии.

Пример из папки проекта при доступных ffmpeg/ffprobe в PATH:

```powershell
python scripts/audit_personal_cz.py --max-streams 60 --budget-seconds 1500
python scripts/build_playlist_site.py
```

Нужны прямой CZ-интернет, без VPN/прокси, Python 3.12+, FFmpeg/FFprobe и curl.
Скрипт сверяет CZ и совпадение IP двумя геобазами, не публикуя домашний IP.
Проверки с GitHub-hosted runners не считаются CZ.

## Обновление

main.yml: прежняя загрузка всех пяти источников раз в 6 часов, без ожидания CZ.
cz.yml: отдельная очередь локального runner каждые 6 часов; сохранение принятых
наблюдений даже после сбоя, импорт на Ubuntu в самый свежий каталог и Pages.
Никакой CZ-job не держит общую очередь обновления во время ожидания компьютера.
Все записи Git используют общую группу iptv-main-writer; Pages имеет свою очередь.
Pages дополнительно пересобирается каждые 6 часов и вызывается после обновлений.
Автоматический запуск не гарантирован ровно в секунду cron: GitHub может задержать его.

Фильтр персонального файла каждый раз применяет строгий допуск заново.
UNKNOWN/OFFLINE не возвращаются из полного исходника при очередной сборке.
Один временный сбой ранее стабильного потока использует предусмотренный льготный
период; повторные ошибки исключают его, проверенный резерв может заменить его.
Пустой/некорректный результат прерывает развёртывание: прошлый сайт сохраняется.
Полный основный плейлист этим персональным отбором не перезаписывается.

Отчёт на Pages: personal-report.json и playlist-info.json/optimized:
поимённый состав, разрешения, даты и язык, группы, число OLED и замен,
причины недопуска. Сами свидетельства сохраняются в Git-каталоге.

## Фоновый запуск Windows

Текущая задача My-IPTV Czech runner скрыта и запускается при входе пользователя.
Для работы без входа в Windows нужна системная служба, а её установка требует
повышенного Windows-сеанса (UAC). Обычная авторизация GitHub этого не предоставляет.
Официальная процедура GitHub: остановить runner в период простоя, удалить его
регистрацию через config.cmd remove с новым remove-token, заново зарегистрировать
через config.cmd --runasservice с новым registration-token и проверить службу.
Токены получать через gh api, не вставлять в репозиторий/публичные инструкции.
Для служебной учётной записи обеспечить чтение Python/FFmpeg/модели и право
записи только в её runner/work/progress. Сначала проверить службу, затем
отключать старую задачу автозапуска. Сон ПК служба сама по себе не отменяет.

Источники:
- https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/configure-the-application
- https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadexecutionstate
- https://github.com/SYSTRAN/faster-whisper

В режиме персональной подборки personal-policy.json/preserve_full_playlist=true
сохраняет полный playlist.m3u без перезаписи. Тот же entrypoint main.yml продолжает
обновлять внутренний каталог из всех пяти источников; персональная сборка Pages
читает этот каталог. Старые и новые варианты не удаляются. Новые открытые ссылки
официальных проигрывателей добавляет personal_sources.py; их доступность с облака
не превращается в CZ-подтверждение. Для диагностики одного канала поддержан
--channel CANONICAL_ID. Персональный отчёт различает число отдельных замеров,
уникальных каналов, декодированные образцы и действительно допущенные записи.

При активной ручной проверке плановый job не запускает второй probe: экспортирует только уже принятые полные checkpoint-записи. Это явно отмечается в логе как 0 новых проверок данного job. Частично записанная последняя строка в artifact не попадает.

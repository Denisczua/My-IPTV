# Подключение самообновляемого My-IPTV по URL

Основной файл репозитория и прежний raw-адрес не удаляются:
https://raw.githubusercontent.com/Denisczua/My-IPTV/main/playlist.m3u

Публичное зеркало того же файла:

- https://denisczua.github.io/My-IPTV/playlist.m3u
- https://denisczua.github.io/My-IPTV/playlist.m3u8

Это два имени одного содержимого, без изменения состава, групп, ссылок,
HTTP-директив и кодировки. Новый отдельный плейлист не формируется.
`playlist-info.json` на Pages содержит число записей, размер, SHA-256 и Git-снимок.
Сравнивать нужно хеши скачанных файлов, а не ETag разных CDN.

## Что проверить в OTTPlayer

В настройках уже успешно загруженного My-IPTV включите автообновление и укажите
прямой Pages URL в поле ссылки автообновления. Поле «ресурс», обозначающее сайт
поставщика IPTV, не заменяет ссылку автообновления. Сохраните настройку и запустите
обновление. По возможности используйте существующую запись плейлиста, чтобы
сохранить её привязку к телевизору и пользовательскую сортировку.

Официальная справка подтверждает форматы M3U/M3U8. Официальное описание
автообновления требует скачивания файла без авторизации; для загруженного вручную
файла можно отдельно указать update URL. Интервал обновления OTTPlayer выбирается
в его настройках и не обязан совпадать с шестичасовым расписанием GitHub.

Источники: [справка OTTPlayer](https://ottplayer.tv/support),
[настройка автообновления](https://ottplayer.tv/news/detail/autoupdate_changes),
[ручное обновление по сохранённой ссылке](https://ottplayer.tv/news/detail/manual_update).
Эти страницы проверены 26 ноября 2026; часть инструкций опубликована давно.

## Диагностика 26 ноября 2026

Raw URL возвращал HTTP 200 без редиректа/авторизации, MIME `text/plain; charset=utf-8`,
полное тело 2 262 208 байт (2,157 МиБ), 10 416 M3U-записей. UTF-8 корректен,
BOM и нулевых байтов нет, переносы LF. Скачивание по HTTP/1.0 с User-Agent старого
curl также завершилось успешно. В заголовке `#EXTM3U` 6387 байт; это зафиксировано
для диагностики, но ограничение длины строки именно OTTPlayer не подтверждено.

В открытой официальной справке и выполненном поиске по официальным доменам не
найдены подтверждённые числовые пределы размера файла и количества каналов.
Отсутствие опубликованного числа не означает отсутствия внутренних лимитов.
Успешная ручная загрузка, о которой сообщил пользователь, не подтверждает,
что серверный загрузчик URL имеет те же тайм-ауты и ограничения.

HTTP 200 и успешная публикация Pages не доказывают подключение в кабинете.
Причина прежнего жёлтого уведомления без его точного текста и ответа сервера
OTTPlayer не установлена. MIME, доступность с серверов OTTPlayer, тайм-аут
скачивания и проверка URL остаются отдельными гипотезами, а не доказанными причинами.
GitHub Pages не позволяет произвольно настроить все HTTP-заголовки; проверяются
реальные ответы платформы для обеих поддерживаемых расширений.

## Автоматическая публикация

`scripts/build_playlist_site.py` валидирует текущий `playlist.m3u` и копирует его
байт в байт в Pages artifact. Пустой/повреждённый M3U не может заменить прежний
развёрнутый сайт. `.github/workflows/pages.yml` публикует только эти зеркала,
небольшую страницу со ссылками и общедоступные данные версии — не диагностическую
базу и не файлы локального runner.

Основной workflow вызывает публикацию сразу после успешного GitHub-hosted
обновления, без ожидания домашнего компьютера, и повторно после принятых
CZ-изменений. Прямое ручное изменение файла и ручной запуск Pages также поддержаны.
Это важно: обычный `push` от `GITHUB_TOKEN` сам по себе не гарантирует запуск
другого push-workflow; используется прямой вызов reusable workflow.

## Критерий завершения

Проблема считается решённой после успешного сохранения URL в OTTPlayer и
обновления списка каналов из него. До этого статус — «ожидает подтверждения
подключения». Если предупреждение повторится, нужны его точный текст, адрес,
который проверялся, и число загруженных каналов. Пароль сообщать не требуется.
